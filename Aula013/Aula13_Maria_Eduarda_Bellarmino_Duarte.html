Etapa 2: Regras: ensinando o Prolog a deduzir

Previsão: Quais respostas terão tio(X, jake) e primo(leo, X)?
tio(X, jake): Jorge não é tio de Jake; a resposta depende das regras definidas no código. primo(leo, X): depende dos fatos e regras de parentesco cadastrados na base.
Previsão: Quais unificações vão falhar: f(X,X)=f(a,b), f(X,X)=f(a,Y), [A|B]=[], 2+3=5?
f(X, X) = f(a, b): falha, pois X não pode ser a e b ao mesmo tempo. f(X, X) = f(a, Y): unifica, pois X e Y podem valer a. [A|B] = []: falha, pois a lista vazia não tem elementos. 2 + 3 = 5: falha, pois o Prolog não calcula automaticamente expressões matemáticas nessa comparação.

Na primeira, não unifica porque X teria que ser a e b ao mesmo tempo. Na segunda, unifica com X = a e Y = a.

3.1 Em tamanho, qual é o caso base e qual é o passo recursivo? O que fica pendente a cada chamada?
O caso base é tamanho([], 0). O passo recursivo conta um elemento e chama a função para a cauda da lista, deixando o cálculo do tamanho pendente.
3.2 Por que concatena(X,Y,[1,2,3]) tem 4 respostas? Compare com anexar do Scheme: o que ele não consegue fazer?
Tem 4 respostas porque a lista pode ser dividida em 4 posições diferentes. O append do Scheme apenas junta listas, enquanto o Prolog também consegue separar uma lista
3.3 membro(X,[a,b,c]) gerou a, b e c sem laço. Que mecanismo do Prolog fez isso?
O mecanismo é o backtracking, que procura todas as possibilidades e retorna cada elemento que satisfaz a consulta.

Etapa 4: Aritmética: onde o Prolog deixa de ser relacional

Previsão: O que mostram X = 2 + 3 e X is 2 + 3? E fatorial(N, 120)?
- `X = 2 + 3`: X recebe a expressão sem calcular. - `X is 2 + 3`: X recebe o resultado `5`. - `fatorial(N, 120)`: dá erro, pois o Prolog não consegue calcular com N livre.
Saída do aritmetica.pl
% Aula 13 - Etapa 4: aritmetica (Sebesta, sec. 16.6)
% "=" UNIFICA (nao calcula). "is" CALCULA o lado direito e unifica com o esquerdo.
% O lado direito de "is" precisa estar totalmente conhecido: aritmetica nao e relacional.
%
% Compare com Haskell (Aula 12):  fact 0 = 1 ; fact n = n * fact (n - 1)

fatorial(0, 1).
fatorial(N, F) :- N > 0, N1 is N - 1, fatorial(N1, F1), F is N * F1.

fib(0, 0).
fib(1, 1).
fib(N, F) :- N > 1, A is N - 1, B is N - 2, fib(A, FA), fib(B, FB), F is FA + FB.

soma([], 0).
soma([H|T], S) :- soma(T, S1), S is S1 + H.

% ---- utilitario: mostra TODAS as respostas de uma consulta (como apertar ; no terminal do Prolog)
consulta(Meta) :-
    \+ \+ ( numbervars(Meta, 0, _), write('?- '), write_term(Meta, [numbervars(true)]), write('.'), nl ),
    (   \+ \+ call(Meta)
    ->  forall(call(Meta), ( write('   '), write(Meta), nl ))
    ;   write('   false.'), nl
    ).

% O programa roda sozinho: a diretiva abaixo chama o main quando o arquivo e carregado.
:- initialization(main).

% tenta/1: como consulta/1, mas mostra o erro (se houver) em vez de parar o programa
tenta(Meta) :-
    catch(consulta(Meta), error(Formal, _), ( write('   ERRO: '), write(Formal), nl )).

main :-
    write('--- = unifica, is calcula'), nl,
    consulta(_ = 2 + 3),
    consulta(_ is 2 + 3),
    consulta(5 =:= 2 + 3),
    consulta(2 + 3 = 5),
    consulta(_ is 7 mod 3),
    consulta(_ is 7 // 2),
    consulta(_ is 2 ^ 10),
    write('--- fatorial, fib e soma'), nl,
    consulta(fatorial(5, _)),
    consulta(fatorial(0, _)),
    consulta(fib(10, _)),
    consulta(soma([1, 2, 3, 4], _)),
    write('--- aritmetica nao e relacional'), nl,
    tenta(fatorial(_, 120)),
    tenta(_ is _ + 1),
    experimentos.

4.1 Explique com exemplos a diferença entre =, is e =:=.
= unifica termos (X = 2+3), is calcula (X is 2+3, resultado 5) e =:= compara resultados (5 =:= 2+3, verdadeiro).
4.2 Por que fatorial(N,120) dá erro e concatena(X,[3],[1,2,3]) funcionou? O que há de diferente na aritmética?
Porque o Prolog precisa que N tenha um valor para fazer os cálculos. Já concatena funciona com variáveis livres, pois é uma relação.
4.3 Compare o fatorial em Prolog com o fact em Haskell: o que é igual e o que é diferente?
Os dois usam recursão e um caso base. A diferença é que Haskell retorna o resultado da função, enquanto Prolog usa argumentos para representar os valores de entrada e saída.
